Laya Vision, in your browser

Typed decisions (choice, score, noul) about an image, computed on this device with ONNX Runtime Web. No server: the image never leaves the page, there is no backend or telemetry. Experimental; read the limitations before trusting a number.

1. Model

By default the model files load from thaitea/laya-vision-web on Hugging Face (fp16 is 475 MB, q8 355 MB; kept in the browser cache after the first load). To use your own export from scripts/export_onnx.py, point this at its folder or pass ?models=<url>.

Limitations

    
    
      
  • Probabilities are conditional on the options you list. They are a softmax over those
        options only, so a question whose true answer is not listed still gets a confident-looking distribution.
        There is no "none of the above" unless you add one.
    • 
      
  • Calibration is not guaranteed on your images. The per-type temperatures were fitted on
        the validation splits of the training data (calibrated ECE 0.02 to 0.03 there). On images unlike that data
        the numbers are scores, not calibrated probabilities, and a high value does not establish that the answer
        is correct.
    • 
      
  • Quantised files are not the PyTorch model. fp32 matches VLMAgent.predict to
        about 1e-5 in probability on the export's validation inputs; fp16 is within about 0.002, q8 about 0.02, and q4
        up to about 0.17, where it can change the top answer (the exporter writes the measured differences to
        validation.json; the page shows its summary after loading).
    • 
      
  • Image decoding differs slightly. The browser decodes the file (and applies EXIF
        rotation, colour management and alpha handling its own way, where PIL does not), then this page
        reimplements the processor's two LANCZOS resizes to 2048 and then 512x512. On test images the result is
        within 0.05 grey levels of the Hugging Face processor on average and 2 levels at most.
    • 
      
  • Only one or two option orders. predict(..., n_permutations=K) averages
        over seeded random orders past the second; those are not reproduced here.
    • 
      
  • State text is serialised like Python's json.dumps; numbers such as
        1.0 or 1e-05 print differently in JavaScript, and the state is cut to fit
        max_len (the page says when).
    • 
      
  • One question at a time, sequentially; there is no batching or prefix caching, so latency grows with the
        number of questions.
